Implement the back-end in .Net 10, C#, Clean Architecture, FreeMediator (https://github.com/steffenskov/FreeMediator), Vertical Slice Architecture, FluentValidation, Xunit tests,
Mediator pattern, Minimal Api, Cross-cutting concerns implemented as behaviors
- Using Microsoft Agent Framework (https://learn.microsoft.com/en-us/agent-framework/workflows/) create a sequential 3 step workflow and expose this workflow as Agent (https://learn.microsoft.com/en-us/agent-framework/workflows/as-agents?pivots=programming-language-csharp)
- Each of the 2 workflow steps are individual agents. Each Agent must take a structured json (or C# DTO) as input and also must output a structured json (or C# DTO)
- The Workflow-As-Agent must speak A2UI, AGUI
- Besides the Agent exposed as an api, there must be no other api endpoints.

Implement the Front-End as an Angular application
- The application must not have any hard-coded UI components, it must dynamically draw it's UI using AGUI and A2UI responses from the backend agent (https://www.angulararchitects.io/en/blog/a2ui-how-ai-generates-dynamic-uis-at-runtime/)
- Use Angular Material library
- The front-end must communicate only to the Agent API, and must not invoke any other api endpoints.
- Do not implement AG-UI, A2UI yourself. Look for libraries, packages which already have these implemented such as Copilotkit

Application Requirements
- In the application, a user will type a free-form text of software project requirements and submit it to the system
- The first step in the workflow will be invoked, which will take the requirements text and convert it into a formal specification, with acceptance criteria. If the LLM has any clarifying questions, those questions 
should be asked from the user using HITL. The human may engage in a conversation to tweak the specification, and utlimately must approve the specification
- After the specification is approved by the human, a second step in the workflow is invoked to convert the specification to a detailed implementation plan. If the LLM has any clarifying questions, those questions 
should be asked from the user using HITL. The human may engage in a conversation to tweak the implementation plan, and utlimately must approve the implementation plan
- For now we will end the workflow here, but in the future we will extend this workflow to be a full coding assistant.


- Whether the human edits the shared session state using the UI or the Agent modifies the shared session state, there is bidirectional state update as shown here: https://dojo.showcase.copilotkit.ai/?integration=langgraph-python&demo=shared-state-read-write
- consider using the prebuilt sidebar for the chat, and the main area to draw the tabs to show the shared session state (https://dojo.showcase.copilotkit.ai/?integration=langgraph-python&demo=prebuilt-sidebar)

we must ensure bi-directional state updates, and we must also use generative-UI...do not write any front-end components, let AG-UI and Copilotkit handle drawing the front-end. These are critical and non-negotiable requirements
